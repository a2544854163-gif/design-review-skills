# Figma 走查检查表

## 文件与版本

- 当前页面、旧稿、探索稿和交付稿是否可区分；
- frame、section、component 和 variant 命名是否稳定；
- 是否存在隐藏重复对象、画布外残留或误用的 detached instance；
- 设计规范、组件页和业务页面是否使用同一套 token。

## 用户流程与原型

- Flow starting point 是否对应真实入口；
- 主操作、返回、取消、关闭、确认和撤销是否有明确去向；
- 弹层、抽屉、键盘、权限请求和系统跳转是否表达清楚；
- 成功、失败、空、加载、禁用、已完成和冲突状态是否按需要覆盖；
- 改期、删除、暂停等操作是否说明影响范围和恢复路径；
- prototype overlay 的位置、关闭方式和背景行为是否合理。

## 组件与变量

- 同一功能是否重复画成多个非组件节点；
- component set 的属性和 variant 是否语义明确；
- 实例 override 是否掩盖主组件缺陷；
- 色彩、间距、圆角、字号和阴影是否绑定变量或样式；
- 交互状态是否通过 variant 表达，而不是复制无关联页面；
- 组件修改是否会意外影响其他业务页面。

## 布局与适配

- Auto Layout 的方向、间距、padding、hug／fill 是否正确；
- 约束和 min／max size 是否支持目标屏幕；
- 文本是否固定高度导致截断；
- 长公司名、岗位名、链接和错误文案是否可容纳；
- 手机四角、安全区、底部导航和弹层是否匹配目标设备；
- 图片、视频和导入素材是否保持比例且不越界。

## 视觉与可用性

- 信息层级是否支持用户快速判断下一步；
- 主次操作是否清晰，危险操作是否区分；
- 文本与背景对比是否足够；
- 触控目标和元素间距是否避免误触；
- 相同状态的颜色、图标、术语和反馈是否一致；
- 装饰是否压过任务信息。

## 交付验收

- 开发所需尺寸、状态和资源是否可读取；
- 图片来自原节点导出而非浏览器截图；
- 核心 frame 在目标设备尺寸下没有遮挡或溢出；
- 原型可以从入口走到完成、取消和主要异常出口；
- 修改后没有新增 detached instance、错误 override 或重复组件。
